## Specs

- S1 Owner (verbatim): "El que voldria es tenir un selector a les opcions on puguis escollir la ciutat on estàs pel temps. Si està definit agafar la ubicació de la tele. El selector entenc que hauria de mostrar les diutats que hi ha openmeteo"
- S2 Owner decision (exact selection): "Cerca Open-Meteo" — the city is typed with the TV keyboard, LlarTV queries Open-Meteo's geocoding API (`https://geocoding-api.open-meteo.com/v1/search?name=…&count=10&language=<ui language>&format=json`) and the owner picks one of the results. Choosing one writes `location=<lat>,<lon>`, `location_name=<name>` and `location_auto=off` to home.conf. Fewer than 2 letters, no result, and a failed request each say so and write nothing.
- S3 Owner decision (exact selection): "Opció 'Automàtic'" — the first choice of the selector: use the Android location of the TV and, when there is none, keep the current city (or Barcelona). New key `location_auto` (on/off, default off, so existing installs keep their city); `location` and `location_name` stay the fallback. With a TV location the card shows only "Open-Meteo" (no reverse geocoding, as #70). Choosing Automatic without the location permission asks for it; with no TV location it says the fallback city is used.
- S4 The weather cache records the coordinates it was fetched for: Home fetches again at once when the place changes, and neither Home nor the screensaver shows weather fetched for another place. An old cache without coordinates counts as another place.
- S5 Documentation: README key table and example, scripts/config.sh keys, SettingsReset keys, CHANGELOG [Unreleased].
