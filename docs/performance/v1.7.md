# LlarTV v1.7 performance (emulator and reference TV, paired)

**Status: the emulator and the reference-TV paired checks are inside every allowance, and the quote acceptance
passes in the three languages on both.** v1.7 changes only the quote corpora (675 short motivational lines per
language) and the version. The emulator numbers are a regression guard; the reference-TV pair is the release gate
(see [the targets](baseline-v1.0.md#targets)).

## Setup

- Target: Android TV emulator `emulator-5554`, AVD `tv11` (the same AVD as v1.6), AOSP TV on x86, Android 11
  (SDK 30), headless, cold boot without saving a snapshot. Same fixture for both versions (Bing wallpaper, default
  dock, Catalan interface), written again after every install; the original `home.conf` was restored at the end.
- Baseline: [published v1.6 APK](https://github.com/almali-dev/almali-llartv/releases/download/v1.6/LlarTV.apk), downloaded
  over HTTPS, 4,266,913 bytes, SHA-256 `d69e594f8f40098429053881b25e594454ac318e5da1858aee87369c20cc89a3` (matches
  [v1.6 performance](v1.6.md#release)).
- Candidate: debug APK built from `feat/v1-7` `42bb798` in a clean detached worktree, 4,227,233 bytes, SHA-256
  `ac05a99e0e8b4939c792059159067eae90c48181995c5ede5b1d6c38cf6da019`; its three quote assets match the source
  files byte for byte (675 rows each). Same signing certificate, installed in place with `install -r -d`.
- Procedure, unchanged from v1.6: `scripts/measure.sh --serial emulator-5554 --apk <apk> --runs 5` (one discarded
  warm-up, five cold starts, five returns from another app, three PSS samples) after a 20 s settle following each
  install. Two alternating rounds: baseline, candidate, baseline, candidate.

each run.

## Quote acceptance (S2, S6)

On the candidate, the emulator clock was set with `cmd alarm set-time` to a day where
`floorMod(epochDay, 675)` selects the planned line, the interface language was set in `home.conf`, Home was
restarted, and a screenshot and a `uiautomator` dump were taken; the clock went back to network time and the
original `home.conf` was restored afterwards. The longest case is the first row tied for the maximum trimmed length
(60 characters); the short case is the shortest authored row, so the author line is checked too.

In every case the quote sits under the date, the author line follows it, the whole text is visible (checked on the

per case, plus `longest-crops.png`) and `.state/v17-emulator/run2/check.log`.

## Reference TV

Xiaomi MiTV-MSSP3, Android 11/API30, with the owner's go-ahead and the owner's own configuration (written again after
every install and restored byte for byte at the end). Before the check the TV ran the Almali branding APK built on
v1.6 (4,267,001 bytes, SHA-256 `0cf06d6e…19a4`, kept to reinstall if needed). The same two APKs as on the emulator
(published v1.6 and the candidate), installed in place with `install -r -d` (no uninstall, no data wipe).
`scripts/measure.sh --serial <tv> --apk <apk> --runs 7` (one discarded warm-up, seven cold starts, seven returns
from another app, three PSS samples), five pairs in an order-balanced sequence: v1.7 first, v1.6 first, v1.7 first,
v1.6 first, v1.7 first, with the memory breakdown kept after every round.

Median of the 35 samples of each version: cold start 1,404 ms against 1,406 ms (+0.1%), Home return 189 ms against
189 ms, RAM 65,387 KB against 65,077 KB (−0.5%). The cold starts fall into two clusters (about 1,350 ms and about
1,620 ms) for both versions, the TV noise already described for v1.6; the first Home return and the first PSS
sample of each round are the slow ones for both versions. The `GL mtrack` category stayed at 13,512–13,768 KB in
every round, so no round measured a different wallpaper bitmap.

The quote acceptance was repeated on the TV with the same six cases and the same method (clock set with
`cmd alarm set-time`, then network time restored): the same texts and author lines as on the emulator, the Catalan
longest line on one line, the Spanish and English longest lines on two, no ellipsis on the screenshots, and the
same 800 px-wide view. No LlarTV entry in the crash buffer. At the end the TV runs the v1.7 candidate as its Home
and screensaver, with its own `home.conf` (byte-identical to the one read before the check) and automatic time.
Evidence: `.state/v17-tv/` (`check.log`, `perf-*.md`, `meminfo-*.txt`, `quotes/`). The TV's `screencap` prefixes
two vendor log lines to the PNG stream; they were stripped before reading the images.

## Release

The published APK is the one built from `main` (`ec3d720`, tag `v1.7`) in a clean detached worktree:
4,227,237 bytes, SHA-256 `029870860bd5a8d616db943dad46d86b43b4f11e3f1ca503caaad9b27f5be158`, versionCode 8,
versionName 1.7, the same certificate as v1.6, so it installs over v1.6 keeping every setting. It was downloaded
again from both public URLs (`releases/download/v1.7/LlarTV.apk` and `releases/latest/download/LlarTV.apk`,
HTTP 200, 4,227,237 bytes each) and both are byte-identical to the published artifact.

The measured candidate above (`42bb798`, 4,227,233 bytes, SHA-256 `ac05a99e…a019`) and the published APK are the
same source for everything that ends up inside the APK; they differ in the documentation commits merged after the
measurement and in four bytes of build metadata, because these builds are not byte-reproducible (the same known
behaviour recorded for [v1.4](../v1.4-acceptance.md)). The measurements were not repeated on the published
artifact.

### On the reference TV

The published APK was installed on the reference TV with `install -r -d` over the measured candidate: the APK
pulled back from the TV is byte-identical to the published one (`0298708…e158`), the UID (`10103`) and
`firstInstallTime` (2026-10-25) are unchanged, so the in-place update kept the data, and `home.conf` was not
touched by the install. Home restarts in 1,480 ms, is still the default Home with LlarTV's screensaver, shows
the quote of 2026-11-03 — "Ensenya més el món que pare i mare.", which is line 511 of `ca.tsv`, the line
`floorMod(20760, 675) = 510` selects — and the crash buffer holds no LlarTV entry.

One difference against the configuration read before the measurement: the TV's `home.conf` has gained the line
`minimal=off`, the default value, written after the measurement run restored the file (the restore was verified
byte-identical at the time). It changes no behaviour and no other key differs.
