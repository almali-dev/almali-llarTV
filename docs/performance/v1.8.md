# LlarTV v1.8 performance (reference TV, paired)

**Status: inside every allowance, and the cold start improves well beyond the measurement noise.** v1.8 moves the
Home wallpaper decode off the main thread (#96); the other three changes of the release are a security fix and two
interface changes with no performance intent. The reference-TV pair is the release gate (see
[the targets](baseline-v1.0.md#targets)).

## Setup

- Target: the reference TV, Xiaomi MiTV-MSSP3, Android 11/API30, with the owner's go-ahead and the owner's own
  configuration, written again after every install and restored byte for byte at the end.
- Baseline: [published v1.7 APK](https://github.com/almali-dev/almali-llartv/releases/download/v1.7/LlarTV.apk),
  4,227,237 bytes, SHA-256 `029870860bd5a8d616db943dad46d86b43b4f11e3f1ca503caaad9b27f5be158`.
- Candidate: debug APK built from `main` `d486cd4` in a clean detached worktree, 4,231,057 bytes, SHA-256
  `4ee4863e2ea335fdf01c009d2f51aebe65b707e169e50277f7bc28f092fb1a5a`. Same signing certificate, installed in place
  with `install -r -d`.
- Procedure, unchanged since v1.6: `scripts/measure.sh --serial <tv> --apk <apk> --runs 7` (one discarded warm-up,
  seven cold starts, seven returns from another app, three PSS samples) after a 20 s settle following each install,
  five pairs in an order-balanced sequence: v1.8 first, v1.7 first, v1.8 first, v1.7 first, v1.8 first.

## Results

Paired comparisons use the mean of each version's five round medians, as in v1.6 and v1.7.

| --- | --- | --- | --- | --- | --- |
| Cold start, median ms | 1434 · 1624 · 1422 · 1408 · 1616 | 1300 · 1364 · 1326 · 1307 · 1306 | −180 ms (−12.0%) | +150 ms and +15% | Inside, and faster |
| Home return, median ms | 263 · 262 · 189 · 200 · 190 | 195 · 193 · 194 · 189 · 183 | −30 ms (−13.6%) | +40 ms and +40% | Inside, and faster |
| RAM, TOTAL PSS, median KB | 67,619 · 63,839 · 71,276 · 70,393 · 70,634 | 70,269 · 70,363 · 70,373 · 70,476 · 70,195 | +1,583 KB (+2.3%) | +4,096 KB and +10% | Inside |
| APK bytes | 4,227,237 | 4,231,057 | +3,820 (+0.09%) | +5% | Inside |

Median of the 35 samples of each version: cold start 1,591 ms against 1,308 ms (−283 ms, −17.8%), Home return
246 ms against 193 ms (−21.5%), RAM 70,393 KB against 70,269 KB (−0.2%).

### The cold-start gain is real, not noise

v1.7's cold starts split into the two clusters the TV has shown since v1.6, about 1,390 ms and about 1,630 ms, and
every round mixes them. v1.8 has no slow cluster at all: 33 of its 35 samples are under 1,400 ms, and its slowest
round (b: 1,536, 1,636, 1,530, 1,364, 1,284, 1,325, 1,292) is the one right after an install. The worst v1.8 round
median (1,364 ms) is still faster than the best v1.7 round median (1,408 ms), so the two versions do not overlap
round by round. This was the condition written into the change's pull request: the gain had to show outside the
roughly 30 ms of run-to-run noise or the change would be reverted. It shows.

### The RAM reading

By round medians v1.8 holds 1,583 KB more, inside the allowance; by the pooled median it holds 124 KB less. The
difference comes from v1.7's round b (63,839 KB), the only round of either version below 67 MB, which pulls its
mean down. v1.8's five round medians sit within 281 KB of each other, so the pooled comparison is the steadier
reading here. The decode now runs on a background thread, which costs one short-lived thread per photo change and
no retained memory.

## The interface changes

- **The saved value in a settings value list (#94).** Checked on the TV with the remote: *Rellotge* shows
  *Segueix el sistema*, *24 h* and *12 h*; with *24 h* saved and the focus moved down to *12 h*, the focus keeps
  the grey row and white text while *24 h* stays in the panel's accent blue. Capture:
  `.state/v18-tv/s-list-focus-moved.png`. The rule that the reset confirmation and the hidden-apps list mark
  nothing is pinned by `SidePanelTest`, **not** checked on screen.
- **The wallpaper off the main thread (#96).** Home shows the photo, the dock keeps its tinted band and the
  capture after the check (`.state/v18-tv/final-home.png`) is the complete screen, so the deferred decode arrives
  as intended.
- **"Sense Internet" (#95): not verified on the TV.** It needs a network that is connected without an uplink, and
  the reference TV has working Internet. The decision is pinned by `NetworkLabelTest`; the text on screen is
  unverified, and this is the one open item of the release.
- **The wallpaper list names (#93).** A JVM test proves the rule; nothing about it is visible on screen.

No LlarTV entry in the crash buffer during the whole check. The owner's `home.conf` was read before the check and
compared again at the end: byte-identical.

While navigating the settings with the remote, OK was pressed twice on *Configuració del sistema* instead of the
row above it, which opened Android's own settings; it was closed with BACK and nothing was changed there.

Evidence: `.state/v18-tv/` (`check.log`, `perf-*.md`, `meminfo-*.txt`, the captures).

## Release

The published APK is the one built from `main` (`32c79a1`, tag `v1.8`) in a clean detached worktree: 4,231,049
bytes, SHA-256 `15a2a0d5ff5a60e83a660176f9d745594921f4c06600b7d1a7394a5aa74bf251`, versionCode 9, versionName 1.8,
the same certificate as v1.7, so it installs over v1.7 keeping every setting. It was downloaded again from both
public URLs (`releases/download/v1.8/LlarTV.apk` and `releases/latest/download/LlarTV.apk`, HTTP 200, 4,231,049
bytes each) and both are byte-identical to the published artifact.

The measured candidate above (`d486cd4`, 4,231,057 bytes) and the published APK differ only in the documentation
commit merged after the measurement and in eight bytes of build metadata: these builds are not byte-reproducible.
The measurements were not repeated on the published artifact, and the reference TV keeps running the measured
candidate, which is the same source.
